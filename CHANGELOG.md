# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **Agents can remember the conversation — `[handler.llm.context]` (`a2a-rs`, `a2a-agents-common`, `a2a-agents`)**: `LlmHandler` started every turn from `[system, user]` and ignored `session_id`, so a "long-running agent" was a stateless function called repeatedly. It can now carry the conversation across turns and keep it inside the model's window. Off by default (`mode = "none"`) — carrying history changes what an existing agent costs and how it answers.
  - **The conversation was already in the database.** `task_history` is append-only, ordered by an autoincrement id, and stores a full `Message` per row; it just could not be read by context. Migration `004` denormalizes `context_id` onto it (a task's context never changes) with an index on `(context_id, id)`, and `005` adds `contexts` and `context_digests`. This mirrors Google ADK, A2A's reference companion, where a `Session` *is* a `contextId` — so `mode = "context"` reads the same rows `tasks/get` does rather than keeping a second transcript that can disagree with it.
  - New `AsyncConversationStore` port — `load` returns the newest digest **and** the messages after its watermark in one call, `compact` appends a digest. Deliberately not split into two ports: a digest written between two separate reads leaves either a gap or duplicated turns in the prompt, and one method makes that boundary something an implementation can actually solve. Implemented by `InMemoryTaskStorage` and `SqlxTaskStorage` over the same state they already keep, plus `NoConversationMemory` so `mode = "none"` is a wired-up choice rather than an absent collaborator.
  - Compaction **appends** a summary with a watermark and deletes nothing. Two turns of one conversation can therefore compact at once: both digests land, the higher watermark wins on load, and the loser is duplicated work instead of a corrupted transcript — which is why no lock is needed across an LLM call.
  - New pure `a2a_agents_common::context` module (`ContextBudget`, `TokenEstimate`/`CharEstimate`, `project`, `fit`, `cap_tool_result`), with no I/O and no protocol types, so the trimming rules — the part with the edge cases — are testable without a database or a model.
  - Trimming gives things up cheapest-first: cap tool results to head+tail, then drop whole tool call/result pairs while keeping the assistant text that concluded from them, then summarize. The system prompt and the message being answered are never touched; a budget too small for those fails naming `max_input_tokens`, because dropping half a question yields a confident answer to something nobody asked.
  - `keep_recent_turns` is honoured by compaction: only what falls before the recent window is folded into a summary, and the digest's watermark is the last message actually summarized. Reading and compacting deliberately use different windows — a load reaches back several of them, because sizing both from one number means the load returns exactly the window compaction may not touch and no summary can ever be written.
  - **A conversation belongs to whoever started it.** Reading conversations back makes a caller-supplied `contextId` decide which conversation you get, so the stores record a `contexts.owner`, claim it on first read, and answer `A2AError::ContextAccessDenied` to anyone else. The owner is the principal the transport authenticated (see the `RequestContext` entry below); on an agent with no `[server.auth]` there is no principal, contexts are unowned, and any caller holding a `contextId` can read one. Note only `jwt` names a *user* (`sub`) — `bearer` and `api_key` name the credential, and `oauth2` names the access token, which rotates. `a2a-agents/docs/authentication.md` has the table.

- **LLM token usage is reported (`a2a-agents-common`)**: neither provider parsed the `usage` block, so nothing measured what a request cost. `LlmResponse` gains `usage: Option<TokenUsage>` and streaming gains a terminal `LlmStreamEvent::Usage`, parsed from OpenAI-compatible `usage` (including `completion_tokens_details.reasoning_tokens`) and Gemini `usageMetadata`. The handler logs it against what it estimated, which is how the estimator's character ratio gets checked against whatever model the config now points at. Streaming usage is opt-in per endpoint (`OpenAiConfig::stream_usage`, on for OpenRouter and OpenAI's own URL) because local OpenAI-compatible servers vary on `stream_options` and one that rejects unknown parameters fails the whole call.

### Changed
- **BREAKING — the authenticated caller reaches the message handler (`a2a-rs`, `a2a-agents`, `a2a-mcp`)**: `http_auth_middleware` authenticated a request and threw the `AuthPrincipal` away, so a handler that keeps per-caller state saw every caller as the same anonymous nobody. The middleware now puts the principal in the request extensions and both transports carry it inward.
  - New `port::RequestContext` — the session id the caller supplied plus the principal the transport authenticated — replaces the `session_id: Option<&str>` parameter on `AsyncMessageHandler::process_message`, `handle_message_flow`, `TaskService::send_message` and `TaskService::send_streaming_message`. One value rather than a fourth positional argument, because a handler that wants one of these usually wants the others, and multi-tenancy is the next field it grows. Handlers that ignored `session_id` take `_ctx: &RequestContext` instead; handlers that used it read `ctx.session_id()`. Call sites with nothing to say pass `&RequestContext::anonymous()`.
  - ConnectRPC reads the principal from `connectrpc::Context::extensions` (the crate moves `parts.extensions` there verbatim); the JSON-RPC and REST routers read it through a `Caller` extractor. A server with no authenticator has nothing in the extensions and names no caller, which is a `None` rather than a failure.
  - `A2AError::ContextAccessDenied` now maps to ConnectRPC `permission_denied` and REST `403` instead of falling through to `Internal`/`500` — it is a refusal, and reported as a fault it invites a retry that will be refused again.
  - `[handler.llm.context] mode = "context"` no longer refuses to start alongside `[server.auth]`. That check existed only because the handler could not tell two callers apart.
- **BREAKING — an over-long request is its own error (`a2a-agents-common`, `a2a-agents`)**: `LlmError::ContextLengthExceeded` splits the one API failure a caller can act on out of `ApiError`, classified from the provider's error body (the status code and shape differ per provider, and several return a plain 400 with prose). It used to reach the handler as `A2AError::Internal("LLM error: API error (400) …")` and simply fail the task; now the handler cuts every tool result to 500 characters and retries once. A refusal with nothing left to drop fails without a second identical round trip, naming `max_input_tokens`.
- **A tool result no longer reaches the model whole (`a2a-agents`)**: tool output was unbounded and the only limit on the loop was `max_tool_rounds`, so one chatty MCP server or one delegated peer reply could exceed the window. Results are now capped to `max_tool_result_chars` (8000 default) keeping the head and the tail, with the elision marked. The progress artifact still carries the full result — only the model's copy is trimmed.
- **`a2a-agents/examples/` cut from 34 files to 9 (`a2a-agents`)**: five `test_*.rs` dev scratch programs, `print_schema.rs` (the `a2a print-schema` subcommand replaced it), three MCP demos, two storage demos, the AP2 merchant agent, five auth configs plus a Keycloak shell script, and four loose fleet/orchestrator TOMLs are gone. What is left is one example per path through the platform, each of which something else in the docs points at:
  - `fleet/` — the flagship walkthrough, merging the old `platform/` and `multi-model/`: three agents from configs on disk, through `a2a up`, to a control-plane deployment, then given models. The per-agent-model material survives as its last section, including the trap it exists for (`OPENROUTER_MODEL` is process-wide, so it moves every unpinned member of a fleet at once).
  - `image-agent/` — new, below.
  - `minimal_agent.rs`, `complex_agent.rs`, `reimbursement_builder.rs`, and `auth.toml` (every `[server.auth]` shape in one commented config).

### Added
- **`examples/image-agent/` (`a2a-agents`)**: a handler written in Rust — a shipping-quote rate table, the everyday reason to reach past TOML — packaged as its own image and deployed like any other agent. `main.rs` reads `A2A_CONFIG`, the `Dockerfile` builds it with its own `ENTRYPOINT` and no `CMD`, `agent.toml` carries `[runtime] image`, and the README walks build → `a2a deploy` → `ps`/`logs`/`stop`, including what the local runtime says when asked to run an image it cannot pull.

- **Per-agent images — `[runtime] image` (`a2a-agents`)**: an agent can name the image it runs from, instead of every agent being the platform's base image plus a TOML file. This is the escape hatch that keeps the declarative layer from being closed: a handler no config can express ships as an image, and the platform goes back to caring only about the config, the port and the container.
  - `AgentSpec` gains `image: Option<String>`, filled from the config by `from_config_path` and by `ControlPlane::deploy`. `ContainerRuntime` runs each agent from its own image where it named one and from the base image (`--image`, renamed builder `with_base_image`) where it did not.
  - Every agent container gets the same contract whoever built the image: the config bind-mounted at `/etc/agent.toml` and named by a new `A2A_CONFIG` variable, `HOST=0.0.0.0`, the configured port published, and the allowed `${VAR}` pass-throughs. The one difference is the command: the base image is started with `a2a run --config …`, someone else's image with **no command override**, so its own `ENTRYPOINT` decides how to boot. Appending an argv from a binary that image has no reason to contain is the alternative, and it fails at run time rather than at deploy time.
  - `LocalProcessRuntime` **refuses** a spec carrying an image (`RuntimeError::Unsupported` → `501`) rather than running the config under `a2a` anyway. It has no image to pull, and the fallback would provision an agent that starts, answers, passes its health probe, and is not the agent that was deployed. `a2a run` on such a config warns for the same reason.
  - `a2a doctor` stops at the image: it reports which image the agent runs from and skips the handler, model-provider and MCP-command checks, which would otherwise be confident answers about a binary that will not run.

- **`CardRefresher` — liveness for the agent registry (`a2a-agents`)**: registry entries were written once (at `a2a run` startup, or by `ControlPlane::deploy`/`recover`) and never revisited, so an agent that died stayed the answer to a skill lookup and kept being handed work. `CardRefresher` re-reads each registered agent's card on an interval (30s) and records what it found. Spawned by both `a2a run` and `a2a control-plane`.
  - `RegisteredAgent` gains `liveness: Liveness { Unknown, Live, Unreachable }`, and `AgentRegistry` gains `mark`. Three states rather than a flag because "we looked and it answered" and "we have not looked" are different facts and only the first is evidence — the same split as `Recovered::{Adopted, Ephemeral}`. `register` leaves `Unknown`, since a config-derived card says nothing about whether the agent is up, and re-registering resets it: that is a new claim about where the agent is, and what was probed was the old address.
  - `find_by_skill` orders unreachable agents **last** rather than dropping them, so a caller taking the first match gets a live peer when one exists and still gets an entry when none does — reporting "could not connect to X" instead of the untrue "nobody provides this skill". A dead agent is never deregistered: hide, never discard.
  - The probe reads the card and deliberately does **not** adopt it. `register` derives the id from the card's `name`, so an agent that renamed itself would land under a second id with the old entry left behind — a duplicate the next skill lookup would happily hand work to. Refreshing card *content* needs an update-in-place that `register` is not.

### Changed
- **BREAKING — a handler this binary cannot serve stops the run (`a2a-agents`)**: `a2a run` fell back to `EchoHandler` with a `warn!` for a `[handler] type` it did not recognise, or for a built-in whose feature was compiled out. The agent bound its port, served a card, answered every request, and did none of what its config said — and a supervisor reading only the exit code saw a clean start. It is now an error naming the handler and the way out: a cargo feature for a built-in that was left out of the build, and `[runtime] image` for a name no build of `a2a` provides. `doctor` reported this as a problem already; now the run agrees with it.
- **BREAKING — `a2a doctor` reports a `reasoning` its provider will discard (`a2a-agents-common`, `a2a-agents`)**: `[llm] reasoning` reaches the wire on `openrouter` only, and everywhere else the only sign was a `warn!` on stderr at startup. `doctor` could not add one either: `SelectedLlm.reasoning` was `Option<Reasoning>` and a dropped setting arrived as the same `None` as a setting nobody wrote, so the report had nothing to distinguish. It is now `ReasoningPlan { Unset, Sent(_), Unsupported(_) }`, and `doctor` warns on the third — a warning and not a problem, since the agent answers either way, just at the model's own thinking default and at a price the config did not choose. Reasoning tokens are billed, which is the whole reason "asked for and dropped" has to be tellable from "never asked for". Sending it on the other providers is still open; `TODO.md` records what each one needs, and both turn on the *model* rather than the provider.
- **BREAKING — delegation peers are resolved when the model calls the tool, not at startup (`a2a-agents`)**: an orchestrator resolved every `[[handler.llm.agents]]` reference once while starting, dialed it, and skipped the entry when the lookup or the connection failed — so an agent deployed a minute later was unreachable for the rest of the orchestrator's life, and its tool was never even advertised for the model to try. A peer that moved kept being dialed at its old address. Under a control plane, agents coming and going is the normal case, not the exception.
  - New `PeerResolver` port with two adapters: `ConnectedPeer` (a transport the caller already holds) and `DiscoveredPeer` (`::at(url)` / `::by_id` / `::by_skill`, which consults the registry per call and dials lazily). The dialed transport is cached by endpoint, since connecting means fetching the peer's card and negotiating a protocol; a lookup returning a different endpoint replaces it.
  - `A2aAgentToolSource::resolving(name, description, peer)` is the new constructor; `new(name, description, transport)` still takes a ready transport and wraps it in a `ConnectedPeer`.
  - The tool is advertised whether or not the peer is up, and an unreachable peer comes back as a tool *result* (`the 'billing' agent is not reachable right now: no agent advertises the 'invoicing' skill`) rather than an error. New `PeerUnavailable` marks that boundary in the type system: not being able to reach a peer at all is something the model can route around, while a failure *during* a delegation means the peer took the work and we lost it, and still fails the run.
  - `a2a run` still reads a card at startup when there is one, for the tool description — `tool_defs` is synchronous and cannot go and ask. With no card, the description now names what the config asked for (`…the 'weather' A2A agent, which provides the 'forecasting' skill`) instead of an endpoint.
- **Delegation waits on the peer's event stream, not a poll timer (`a2a-agents`)**: `A2aAgentToolSource` sent the peer a task and then re-read it every 250ms until it went terminal. It now prefers `subscribe_to_task` and keeps polling only as the fallback — for a peer with no streaming backend, or one whose stream drops before the task finishes, in which case the task is re-read after the stream ends so neither mechanism failing can turn a finished task into a timeout. Same shape as the `a2acli send` wait, and for the same reason: a subscription wakes on the peer's actual progress rather than on a timer, so a peer answering in 20ms is relayed in 20ms instead of at the next tick.

### Fixed
- **Task history could come back in the wrong order (`a2a-rs`)**: `SqlxTaskStorage::load_task_history` ordered by `timestamp`, whose default is `datetime('now')` — second resolution in SQLite — so rows written in the same second had no defined relative order. Nobody noticed while history was short and read for display; rebuilding a conversation from it puts turns in the wrong order at random. It now orders by `id`, the autoincrement insertion order, which is also what the conversation log means by sequence. The same query filtered out `NULL` messages *after* applying `LIMIT`, so `history_length = 5` returned fewer than five whenever a status transition carried no message; the filter moved into the query.
- **Every outbound HTTPS call failed behind a TLS-intercepting proxy (workspace)**: `reqwest` was built with `rustls-tls` alone, whose trust anchors are the compiled-in webpki roots. rustls does not read `SSL_CERT_FILE`, so a CA installed on the machine — a corporate MITM gateway, or a [Docker Sandbox](https://docs.docker.com/ai/sandboxes/) configured to re-sign egress — could not be trusted from outside the binary at all. Every LLM call, remote-peer delegation and MCP-over-HTTP request died as `Network error: error sending request for url (…)`, with the certificate error dropped from the message and `curl` in the same shell working fine. The workspace dependency now also enables `rustls-tls-native-roots`; reqwest's two root stores are additive, so the built-in roots remain the floor for a machine with no trust store and the OS store adds whatever the operator installed. The TLS decision now lives once in the workspace `Cargo.toml` rather than in three crates.
- **Delegating to an agent that asked a question hung until the deadline (`a2a-agents`)**: the wait stopped at a *terminal* state, so a peer replying `input-required` or `auth-required` — stopped, waiting on its caller — was polled for the full 60s and then reported as "did not finish". The peer had answered in milliseconds; nobody was ever going to answer its question, because the caller is a model that had already been told the tool timed out. The wait now stops at `is_settled`, the same set the spec's blocking `SendMessage` and the subscription-close rule use.
- **A peer that failed was relayed to the model as an answer (`a2a-agents`)**: the tool result was the peer's status message text whatever state the task ended in, and a `failed` task's message reads exactly like an answer ("I could not find that invoice"). So an orchestrator handed a failure onward as a result, which is the same silent-wrong that `LlmHandler` had returning `Ok` on a run that gave up. A completed task's reply still goes back bare — it is the answer, and framing it would put words in the peer's mouth — while every other settled state is now labelled with what happened (`the 'billing' agent failed the request: …`), so the model can try another agent or say so rather than repeating an apology as fact.

- **BREAKING — a broken LLM provider stops the agent instead of degrading it (`a2a-agents-common`, `a2a-agents`)**: `provider_from_env` returns `Result<Option<SelectedLlm>, LlmConfigError>` and `provider_from_settings` returns `Result<SelectedLlm, LlmConfigError>`, separating "nothing is configured" from "what is configured does not work". Both used to collapse into `None` (or, for a bad `[llm]` block, into a fallback to the environment), so a mistyped provider, a missing key, or a typo'd `OPENROUTER_REASONING` produced an agent that started clean and answered every message from its non-LLM stub.
  - `a2a run` now fails to start on an unusable provider, naming the setting. `Ok(None)` — nothing configured at all — still runs the deterministic fallback.
  - A failing provider no longer falls through to the next one in the cascade: a broken `OPENROUTER_API_KEY` must not silently promote whatever else the environment holds.
  - `a2a doctor` builds the provider the same way `a2a run` does (`Requirement::LlmProvider(LlmSource)` carries the config's `[llm]` settings), instead of inferring a verdict from which variables are set. It reports an unusable provider as a problem, a missing one as a warning, and names the resolved provider and model when it works.
  - `provider_from_settings` fills anything the config omits from that provider's own environment variables — key, model, base URL. Previously only `openrouter` looked: a `[llm] provider = "gemini"` block with its key in `GEMINI_API_KEY` built an empty key and failed at the endpoint, after `doctor` had reported the key as found.
  - `SelectedLlm` carries the resolved model, so `a2a run` logs provider *and* model for env-selected providers (it only did so for TOML-configured ones).
  - A variable set to whitespace now reads as unset everywhere, which is what a commented-out line in a `.env` file leaves behind.

### Added
- **`[llm] reasoning` (`a2a-agents`, `a2a-agents-common`)**: how hard a model should think is now the config's decision — `reasoning = "off" | "low" | "medium" | "high"`, or a token budget (`reasoning = 1000`). It sits beside `model` because that is what it belongs to: a flash model answering in one line and a frontier model doing analysis want different answers, and the *handler* serving them cannot tell which it was pointed at. Omitted, nothing goes on the wire and the model's own default stands. A request may still override it (`LlmRequest::reasoning`), which is how `complex_agent` streams thinking whatever the config says. `Reasoning` owns its own string form, so `[llm] reasoning`, `OPENROUTER_REASONING`, and the error message that lists the valid values all come from one parser; a misspelt level fails at load rather than quietly costing money. Reaches the wire on `openrouter` today — other providers log the setting they are dropping instead of pretending to honour it.

- **Multi-model fleet example (`a2a-agents/examples/multi-model/`)**: three specialist agents, each pinned to a *different* OpenRouter model, plus an orchestrator that finds them by skill — one `OPENROUTER_API_KEY`, four models, one process. The per-agent model story was expressible but undemonstrated, and the one thing that makes it work is easy to get backwards: `[llm] model` is per config, while `OPENROUTER_MODEL` is per *process*, so a fleet driven from the env var silently collapses onto one model. Each member pins its own, and `a2a run`/`a2a up` now log the model alongside the provider so the split is visible at startup rather than inferable from the bill. The README records the verified model ids and prices with the date they were read, since both move.
- **`every_shipped_example_fleet_validates` (`a2a-agents`)**: the fleet test discovers every `examples/**/fleet.toml` instead of naming one, so an example added later is covered without anyone remembering to add it — the failure mode of a hard-coded list is that it quietly stops being the whole set.
- **`a2a new --fleet <toml>` (`a2a-agents`)**: scaffolding an agent can now add it to a fleet file, creating the file if it is not there — so `a2a new Weather --fleet demo.toml && a2a new Router -t orchestrator --fleet demo.toml && a2a up -f demo.toml` builds and runs a multi-agent system with nothing hand-written. `a2a up` defaults to `./fleet.toml` and nothing produced one, which left the fleet shape as something to type from an error message. Members are appended as text rather than through a `toml::to_string` round-trip: a fleet file is hand-written and carries comments and ordering that re-serializing would silently discard. The path recorded is relative to the fleet file whenever the config sits under it (so the fleet stays portable) and absolutized otherwise; `member_path` is the pure inverse of `FleetConfig::config_paths` and is tested as a round trip.
- **`a2a ps --all` (`a2a-agents`)**: shows agents that have been stopped, which `ps` now hides. See below.
- **`a2acli send --no-wait` / `--wait-timeout` (`a2acli`)**: control over whether `send` follows the task to a reply. See below.
- **`a2acli list` (`a2acli`)**: `list [--state …] [--limit N] [--context-id ID]` — the `Transport` port already had `list_tasks` and nothing exposed it, so a task id you lost was a task you could not reach again. `--state` is a `ValueEnum`, so `--state nonsens` is rejected by the parser with the valid values listed rather than becoming a filter that silently matches nothing. Human output is one line per task (id, state, the opening of the last thing said on it) and reports `(N of M shown)` when the server's total exceeds the page, since "everything" and "everything that fitted" are different answers.
- **`a2acli send -` reads the message from stdin (`a2acli`)**: for a prompt too long or too quote-heavy to be an argv element. The trailing newline is stripped — it is an artefact of how the text arrived, not part of what was meant.
- **`WebA2AClient::auto_connect_with` (`a2a-client`)**: the web client had the same gap the CLI did — it could only auto-connect anonymously, so an authenticated agent was reachable only by hand-building a transport and skipping negotiation. Takes the same `ClientConfig`, which is re-exported from `a2a-client` so callers need not depend on `a2a-rs` directly.
- **End-to-end tests for the `a2acli` binary (`a2acli/tests/cli_e2e_test.rs`)**: every other client test drives the `Transport` port in-process; these run the **built binary** as a child process against a live JSON-RPC agent on an ephemeral port, covering `card`/`send`/`get`/`cancel`, both halves of the wait (subscription and poll fallback, each against an agent shaped to force that path), `--no-wait`, an expired `--wait-timeout`, `--auth` against a card endpoint that demands a bearer token, and a malformed URL exiting non-zero. The streaming test asserts the agent actually served a subscription, so it cannot quietly pass on the polling fallback.
- **Container hardening (`a2a-agents`)**: `ContainerHardening` applies `--cap-drop=ALL`, `--security-opt=no-new-privileges`, a 512-process cap, and — where the agent's storage permits it — a read-only root filesystem with a `/tmp` tmpfs; the base image now runs as uid 10001. The read-only decision is derived from the config (`needs_writable_rootfs`) rather than left to the operator, because being wrong is invisible in both directions: a read-only `sqlx` agent crash-loops on a disk error that names nothing useful, and a writable in-memory one gives up the protection for free. Resource ceilings are deliberately opt-in (`--memory`, `--cpus`) — no default is right for every agent, and a guessed one surfaces as an agent dying under load for no visible reason. `--no-hardening` is the escape hatch and warns, like `--no-auth`. This is the cheap 80% of isolation; a container-run agent is **contained**, not *isolated*.
- **`a2a deploy` / `ps` / `logs` / `stop` — the CLI half of the control plane (`a2a-agents`)**: the server half already existed and nothing but `curl` could work it, which left the whole daemon story reachable only through Terraform. The same binary is now both halves, over a new first-class `ControlPlaneClient` adapter (the Terraform provider will target the same routes). `--url` / `--token` fall back to `A2A_CONTROL_PLANE_URL` / `A2A_CONTROL_PLANE_TOKEN` and then to where `a2a control-plane` binds, so a control plane in one terminal and these commands in another need no configuration to find each other.
  - Configs are deployed **raw**: `${VAR}` is expanded by the control plane against *its* environment and *its* `--allow-env` allowlist. Expanding client-side would put the operator's secrets on the wire, require every deploying machine to hold them, and bypass the allowlist entirely.
  - `deploy` takes `--config` (repeatable) or `--fleet <toml>`, and checks shape plus the cross-agent conflict rules *before sending anything* — a port clash knowable up front must not leave half a fleet deployed.
  - The request/response bodies now live in one place (`control_plane::wire`), shared by the router and the client, so the two sides cannot drift.
- **`AgentRuntime::logs` (`a2a-agents`)**: health says an agent is `unhealthy`; this says why. `GET /agents/{id}/logs?tail=N` on the API, `a2a logs <id> [--tail N]` on the CLI. `ContainerRuntime` replays through the engine, merging **both** streams — an agent's `tracing` output goes to stderr, so reading stdout alone showed an empty log for a crashing agent. `LocalProcessRuntime` captures each agent into `<log-dir>/<id>.log` (`a2a control-plane --log-dir`, defaulting to `<config-dir>/logs`), which also stops every agent's output interleaving into the supervisor's terminal unlabelled.
- **Restart-recovery for the control plane (`a2a-agents`)**: a bounced control plane used to come back reporting an empty fleet while its agents were still serving — `GET /agents` returned `[]`, `DELETE` returned 404, peers stopped resolving each other by skill, and a Terraform `Read` would conclude the agents had been destroyed and recreate them on top of the running ones. New `AgentRuntime::recover` adopts what the backend is still running, and `ControlPlane::recover` re-registers the adopted agents' cards so discovery is rebuilt *from the runtime* rather than from a database. `a2a control-plane` runs it before binding, so the API's first answer is true.
  - The return type is `Recovered::{Adopted, Ephemeral}`, because "nothing was running" and "I cannot tell what is running" are different answers and only the first may be reported as an empty fleet. Every adapter must state which — there is deliberately no defaulted trait method.
  - `ContainerRuntime` rebuilds its `AgentId → port` map from `docker ps -a --filter label=a2a-agent`; provisioning now also stamps the published port as a label so the map is recovered whole rather than half. `LocalProcessRuntime` answers `Ephemeral` (its children die with the supervisor), which is the concrete reason container is the supported control-plane backend.
  - New `CardSource` port (+ `HttpCardSource` / `InMemoryCardSource`) so re-registration does not put an HTTP client in the service layer, and recovery is testable without a network.
- **`a2a doctor` — pre-flight check (`a2a-agents`)**: `validate` answers "is this config well-formed"; `doctor` answers "will it work on this machine" — is the port free, is the MCP server's command on `PATH`, is a model key set, does every `${VAR}` resolve *here*, is a container engine installed, and can the configs named actually run together. Split so the rules are testable: `core::doctor::requirements` derives what a config needs purely from the config, and the binary probes the host (bind the port, search `PATH` honouring `PATHEXT`, read the environment). Only *problems* set the exit code; warnings describe something that will run, differently than you may have meant. Deliberately stricter than `validate` on one point — an unset `${VAR}` is reported there and fatal here, because `a2a run` refuses to start until it resolves.
- **`a2a up` — run a fleet from one file (`a2a-agents`)**: a fleet file lists member agent configs by path (resolved relative to itself, so a fleet runs from any directory), replacing a `--config` per agent on every invocation with one reviewable artifact. It redefines nothing about an agent — `AgentConfig` stays the source of truth — and adds the checks that only exist *between* members, run before anything binds: two agents claiming the same **port**, and two names that slugify to the same **registry id**. Both are silent-wrong at runtime (a bind error buried in a process that otherwise came up; registration upsert, so delegation by skill/`agent_id` reaches only the last one). `a2a validate --fleet <toml>` runs the same check without starting anything and reports every conflict rather than the first; `a2a print-schema --fleet` emits the `FleetConfig` schema. New `core::fleet` module (`FleetConfig`, `fleet_conflicts`) plus `examples/fleet.toml`.
- **`a2a new` — scaffold an agent config (`a2a-agents`)**: `a2a new <name> [--template echo|llm|mcp|orchestrator]` writes a commented, immediately-runnable TOML and prints the next commands. Templates are written to be *read* — every non-obvious key carries a comment — so a generated file answers "what else can go here?" without `print-schema`. `--output`, `--port`, `--force`; an existing file is never clobbered by default. Rendering lives in `core::template` as a pure function (file I/O stays in the binary), and tests pin the two invariants that make a scaffold trustworthy: every template must *validate*, and no template may reference `${VAR}` — a freshly scaffolded agent has to run without the user setting something first.
- **Control-plane authentication (`a2a-agents`)**: `ControlPlaneAuth` (bearer token, constant-time compare) is a **required parameter** of `control_plane_router`, so an unauthenticated control plane cannot happen by omission — `ControlPlaneAuth::Disabled` has to be written out. `a2a control-plane` refuses to start without `--token` / `A2A_CONTROL_PLANE_TOKEN` unless `--no-auth` is passed, which warns loudly.
- **Secrets allowlist for deployed agents (`a2a-agents`)**: `EnvAllowlist` (deny-by-default) replaces "inject whatever the config references". Configured once at the composition edge (`--allow-env VAR`, repeatable) and given to both the `ControlPlane` (vets what the API accepts) and the runtime adapter (decides what crosses into the agent), so the runtime stays safe even when something other than the service drives it. The check runs against the **raw** TOML before parsing, because parsing expands `${VAR}` and reports set vs. unset differently — otherwise a config naming a forbidden secret is a probe for which secrets the control plane holds.
- **`a2a validate` reports unresolved env refs (`a2a-agents`)**: unset `${VAR}` references no longer fail the check; they are substituted with a placeholder and listed, so a config's *shape* is verifiable without the secrets it will run with (`AgentConfig::check_toml`). `--strict-env` restores hard failure as a pre-deploy gate. Leniency is scoped to missing values only — structural checking is untouched.
- **`a2a run` startup banner (`a2a-agents`)**: prints each agent's name, URL, card URL, and a copy-pasteable `a2acli send` / `curl`, on stdout rather than through `tracing`.
- **Protocol-binding constants (`a2a-rs`)**: `PROTOCOL_BINDING_JSONRPC` / `_CONNECTRPC` / `_HTTP_JSON` in `domain`, shared by the agent-card builder and the client negotiation factories so the two sides cannot drift apart.
- **Declarative multi-agent platform (`a2a-agents`)**: `a2a-agents` grew from a single-agent builder into a platform for running and orchestrating *many* agents, with every outward capability defined as a **port** so the core `a2a-rs` protocol crate stays infrastructure-free.
  - **Agent-as-tool delegation**: a config-driven `LlmHandler` (behind the `llm` feature) can call peer A2A agents and MCP servers as tools — an orchestrator delegates work by listing peers under `[[handler.llm.agents]]` and tool sources under `[[handler.llm.mcp]]`. The handler no longer depends on `mcp-server`; LLM provider selection routes through the shared provider helper.
  - **Registry / discovery**: the `AgentRegistry` port + `InMemoryAgentRegistry` let agents find peers by **skill** instead of hard-coded URLs. Config refs resolve by `skill`/`agent_id`; the `a2a` binary self-registers in a two-phase startup.
  - **Runtime / isolation**: one `AgentRuntime` port supervises agents as local processes or OCI containers — `LocalProcessRuntime`, `ContainerRuntime` (CLI shell-out backend), and `InMemoryAgentRuntime` for tests. Sandboxing lives in the platform, not in `a2a-rs`.
  - **Control plane**: a `ControlPlane` service composes runtime + registry behind an HTTP API; `a2a control-plane` deploys, lists, and tears down agents (deploy is async).
  - **`terraform-provider-a2aagent`** (WIP): a Terraform provider for declaring agents as infrastructure.
- **OpenRouter LLM provider + reasoning (`a2a-agents-common`)**: added an OpenRouter provider with centralized provider selection and reasoning-token support; the `complex_agent` example streams GLM reasoning and answer tokens live over SSE.
- **Platform lifecycle example (`a2a-agents`)**: `examples/platform/` — a worked walkthrough of the control-plane lifecycle (`examples/fleet.toml` stops at `a2a up`), with a README plus greeter/notifier/fleet configs. Echo handlers and no API keys, so it runs anywhere.
- **`a2acli` command-line client**: a new CLI driving the `a2a-rs` `Transport` port — `card`, `send`, `get`, `cancel`, `stream`. Endpoint from `A2A_URL` (`--url`/`-u`); `--transport auto|connectrpc|jsonrpc`; `--json` for machine-readable output. Auto mode negotiates the transport from the agent card with a direct-client fallback, doubling as a manual cross-SDK interop harness. `auto_connect` was promoted into `a2a-rs` and is now shared by the CLI and web client.

### Changed
- **BREAKING — reasoning is asked for by the caller, not inferred from the endpoint (`a2a-agents-common`)**: `LlmProvider::supports_reasoning` is **removed**, `ReasoningConfig` is replaced by `Reasoning { Off, Effort(_), Budget(_) }`, and `LlmSettings`/`OpenAiConfig` carry an optional default. The old arrangement had every caller sniff a capability and then decide: `LlmHandler` asked for **high** effort whenever the provider said it could reason — a fact about the *endpoint* (OpenRouter, always true) and not about the model — so every OpenRouter agent paid for frontier-grade thinking, including a flash model answering weather questions; `complex_agent` read `OPENROUTER_API_KEY` from the environment to make the same guess. Now a caller says what it wants and the adapter decides what the wire can carry: an endpoint with no such parameter (plain OpenAI, Ollama) sends the request *without* it rather than failing, so asking is always safe. `Reasoning::Off` also expresses something the old effort-only type could not — turning thinking off, which is what a small fast model usually wants. The unused `exclude` knob went with it; nothing could set it.

- **BREAKING — `a2a ps` hides stopped agents (`a2a-agents`)**: `ControlPlane::list` and `ControlPlaneClient::list` take a `ListFilter` (`Live` / `All`), and `GET /agents` defaults to live with `?all=true` for the rest. A runtime keeps an entry after an agent stops — deliberately, because that is when its log matters most and `a2a logs` still answers for it — but `undeploy` says it removes the agent from discovery, and one that kept appearing in `ps` read as one that refused to go away. Same split as `docker ps` / `docker ps -a`, and for the same reason: hidden, never discarded. In-workspace call sites are updated in the same change (pre-1.0, no shim).
- **BREAKING — `a2acli send` waits for the agent's reply (`a2acli`)**: it waits for a terminal or interrupted state (30s, `--wait-timeout`), because agents that answer asynchronously return `working` from `send` and deliver the reply on a later `get` — so an agent scaffolded from the `llm` or `orchestrator` template showed nothing at all on first contact. `--no-wait` restores the old behaviour. If the budget runs out the task is printed as it stands, followed by the `stream`/`get` commands that follow it.
- **`a2acli send` waits on the event stream, not a poll loop (`a2acli`)**: the wait now prefers `subscribe_to_task` and keeps polling only as the fallback. Against a conformant server this path does not run at all (the task comes back settled); what it is *for* is a peer that ignores `return_immediately`, and there a subscription wakes on the agent's actual progress rather than on a 250ms timer, and ends by itself the moment the task settles. Polling remains for a peer with no streaming backend, or one whose stream drops before the task finishes — the wait re-reads the task after the stream ends and resumes polling if it is still unsettled, so neither mechanism failing can turn a finished task into a timeout. The "waiting up to Ns…" notice is now on a timer of its own, so a fast agent still prints nothing.
- **BREAKING — `--auth` / `--timeout` work in `auto` transport mode (`a2acli`, `a2a-rs`)**: transport negotiation built unauthenticated, default-timeout clients, so credentials applied only when a transport was pinned with `--transport` — and the CLI could do no better than log a warning that it was ignoring them. New `ClientConfig` (token + timeout) is threaded through negotiation: `TransportFactory::create` takes one, alongside `TransportNegotiator::negotiate_with`, `connect_with`, `auto_connect_with`, and `fetch_agent_card_with`. The **card fetch carries the credentials too** — an agent that guards its RPC endpoints usually guards its card, and a 401 there sank the whole negotiation before any of it could be authenticated. Breaking for anyone implementing `TransportFactory`; the no-config `negotiate` / `connect` / `auto_connect` / `fetch_agent_card` entry points are unchanged and now delegate with `ClientConfig::default()`.
- **The `orchestrator` template scaffolds on port 8090, not 9090 (`a2a-agents`)**: 9090 is where `a2a control-plane` binds, and an orchestrator plus a control plane is exactly the pair someone runs together. The collision was silent — the losing bind read as the agent simply not answering. Both scaffolded ports now sit in the 80xx band; `examples/orchestrator_agent.toml` and `examples/registry_orchestrator.toml` moved with them.
- **BREAKING — minimum supported Rust version raised to 1.96 (all crates)**: every crate declared `rust-version = "1.85"` while the dependency graph had already moved past it (`icu_*` require 1.86, `process-wrap` 1.87) — a claim that was simply false, and that surfaced only when the agent container image failed to build on its pinned `rust:1.85` builder. Cargo errors when the *toolchain* is below a dependency's floor, never when `rust-version` is, so nothing catches this on a developer machine. Set to 1.96 rather than the bare 1.87 minimum deliberately: that is the toolchain the workspace is built and tested with and the one the Dockerfile pins, making the claim one we exercise rather than a guess. It is now declared once in `[workspace.package]`, with members inheriting it, so the seven copies cannot drift apart again.
- **BREAKING — `AgentRuntime` gained a required `logs` method (`a2a-agents`)**: no default implementation, for the same reason `recover` has none — a backend that keeps no logs must return the new `RuntimeError::Unsupported` (surfaced as HTTP 501) rather than an empty list, because "the agent printed nothing" and "this runtime does not record output" send an operator to opposite places. All in-workspace adapters are updated in the same change (pre-1.0, no shim).
- **BREAKING — `AgentRuntime` gained a required `recover` method (`a2a-agents`)**: no default implementation, so every adapter has to state whether it can be recovered after a restart. A default returning "nothing" would have been the exact silent-wrong this feature exists to remove. All in-workspace adapters are updated in the same change (pre-1.0, no shim).
- **BREAKING — `ControlPlane::new` takes a `CardSource` (`a2a-agents`)**: recovery has to fetch a running agent's card to put it back into discovery, and a control plane that silently skipped that step would come back from a restart supervising agents nobody can find. Required rather than optional for that reason.
- **BREAKING — unknown config keys are now errors (`a2a-agents`)**: every config struct is `#[serde(deny_unknown_fields)]`. Previously a mistyped key was silently ignored, so `http_prot = 9999` validated clean and then served on 8080 — the config lied and the checker agreed. Errors now point at the line, name the key, and list the valid ones. Configs carrying stray keys will start failing; all 17 shipped examples were already clean.
- **BREAKING — control-plane deploy is gated by a token type (`a2a-agents`)**: `ControlPlane::prepare(raw_toml)` returns a `PreparedDeploy` that is the only thing `deploy` accepts, making the policy check unskippable by construction rather than by convention. `control_plane_router` gained a required `ControlPlaneAuth` argument. In-workspace call sites are updated in the same change (pre-1.0, no shim).
- **BREAKING — runtime type renamed (`a2a-agents`)**: the old single-agent server type `core::AgentRuntime<H, S>` is now `AgentServer`; `AgentRuntime` is the new platform runtime **port**. In-workspace call sites are updated in the same change (pre-1.0, no shim).
- **Validation output is CLI output (`a2a-agents`)**: `a2a validate` results go to stdout without timestamps, levels, or module paths — one indented block per file with a summary line. Long-running commands (`run`, `control-plane`) still use `tracing`.
- **`handler.type` is a typed enum (`a2a-agents`)**: `HandlerType { Echo, Llm, Reimbursement, Custom(String) }` (parse, don't validate) replaced a stringly-typed `!= "echo"` check; the binary matches on it, with `Custom`/unsupported falling back to echo and warning. `a2a doctor` reports such a config as a problem, since a config that looks configured behaving like a stub is exactly the silent-wrong the tool exists to catch.
- **`ControlPlane::deploy` no longer touches the filesystem (`a2a-agents`)**: it takes an already-parsed `AgentBuilder`, so the TOML is parsed once and the HTTP adapter writes it with `tokio::fs` — no blocking I/O on the executor, and the service layer stays free of the filesystem (hex rule 9a).

### Fixed
- **An LLM agent that gave up reported success (`a2a-agents`)**: `LlmHandler` ended a tool-call budget overrun with `Ok("I could not converge on an answer within the tool-call budget.")` — a **completed** task whose text said it had failed. Every caller that branches on state read that as success: `a2acli` exits `2` on `failed` and so exited `0`, and agent-to-agent delegation relayed the apology onward as if it were an answer. It now settles **failed**, naming `max_tool_rounds` as the knob that changes it, and keeps whatever the model said on the way instead of replacing it — a failed task's most useful content is the partial work. `failed` rather than `input-required` because the agent asked the caller no question: prompting for input would restart the same run against the same budget. This and the empty completion below were the same missing outcome — a run that finished without breaking *and* without delivering — so `run_with_llm` now returns `Answer::{Given, GaveUp}` and the two share one representation rather than two patches.
- **An LLM agent that said nothing reported success (`a2a-agents`)**: `LlmHandler` returned whatever content the model streamed, empty included, and completed the task with it. Proto3 omits a default value, so an empty text part goes on the wire as `{}` — indistinguishable from a file or data part — and the client renders it as `[non-text content]`. So the agent came back *completed*, showed a line about binary content it had never produced, and named neither the cause nor the model. Reached easily: a small model can spend its entire response budget on reasoning and emit no answer — the first request to the new multi-model example did exactly that, back when high effort was requested for every reasoning-capable model (see `[llm] reasoning` above). An empty completion now fails the task with a message that says which of the two happened, because a task that finishes with nothing to show is a failure whatever the transport thinks.
- **BREAKING — a task the agent failed exited `0` (`a2acli`)**: the request succeeding and the *work* succeeding are different facts, and the CLI reported only the first — so `a2acli send "ship it" && ./deploy.sh` deployed on a failed task. `send` and `get` now exit **`2`** when the task's state is `failed` or `rejected`, distinct from `1` (the command itself failing) because a timeout is worth retrying and a refusal is not, and one exit code cannot ask for both. Only the agent's own verdicts count: a task still working is not a failure (the caller was told how to follow it), and `cancel` still exits `0` on a canceled task — that is the command working. The task is still printed to stdout in full; the reason goes to stderr.
- **The CLI fell silent exactly when the agent asked a question (`a2acli`)**: `input-required` and `auth-required` are *settled* states, so the "still working, follow it with…" hint did not fire and nothing replaced it — the agent had handed the conversation back and the output read like it had given up. `send` and `get` now print the command that answers on the same task (`send --task-id <id>`), which is the one thing that continues the exchange and the one thing the previous hints never mentioned.
- **A bearer token could be logged in full (`a2a-rs`)**: `ClientConfig` derived `Debug`, so a single `tracing::debug!(?config)` wrote the credential to the log — and this type is precisely what a caller reaches for when tracing *why* a connection did not authenticate, making the most likely line to be written the one that leaks. `Debug` is now hand-written and prints `<redacted>` when a token is set (and `None` when it is not, so the rendering still distinguishes the two cases).
- **A valid-looking URL panicked instead of erroring (`a2a-rs`, `a2acli`)**: `HttpClient::new` ends in `.expect("Invalid base URL")`, while `auto_connect` validated with `reqwest::Url::parse` — which is *more* permissive than the `http::Uri` the ConnectRPC client needs. `reqwest::Url` accepts an IDN host like `http://münchen.de` and normalizes it to punycode; `http::Uri` rejects the raw bytes. The original string was then handed to `HttpClient::new`, so `a2acli --url http://münchen.de send hi` aborted on a URL the same function had just declared valid one line earlier. Worse, the panic sat on the *fallback* path, which is where a questionable URL is most likely to end up in the first place. New `HttpClient::try_new` / `try_with_auth` return `Result`; negotiation, the direct-client fallback, and `a2acli --transport connectrpc` all use them, so a URL the transport cannot represent is now an `InvalidParams` error naming it. `new` / `with_auth` remain as the panicking convenience for a hardcoded literal, now documented as such. The `ConnectRpcTransportFactory` also drops its own duplicate pre-validation — the knowledge that this URL has to be an `http::Uri` now lives in one place.
- **`a2a doctor` warned about capabilities nothing had asked for (`a2a-agents`)**: the environment report flagged a missing model key and a missing container engine on every run, whether or not any config being checked wanted one — so a scaffolded `echo` agent came back "all clear" on a laptop with `OPENAI_API_KEY` exported and warned on a machine without it. The per-config requirements already answer this precisely (`Requirement::LlmProviderFromEnv` fires for `llm` handlers and not for `echo`), so absence is now only a warning for bare `a2a doctor`, where the environment report is the whole output and nothing else would mention it. A check whose result depends on the host's unrelated state is one people learn to ignore, which is the opposite of what a pre-flight tool is for. The test that should have caught this asserted "all clear" while inheriting the developer's own environment; it now has a sibling that clears every var `llm_env_var` consults in the *child* process — `std::env::remove_var` would have mutated the environment of every other test on the same binary's thread pool.
- **BREAKING — `SendMessage` ignored `return_immediately`, and defaulted to the opposite of the spec (`a2a-rs`)**: the field existed on the generated type and was read nowhere, so the server always behaved as if it were `true` — it acknowledged the message and returned `WORKING`. The proto3 default is `false`, and `false` obliges the server to wait until the task reaches a terminal or interrupted state before returning (`spec/a2a.proto:155`). A conformant client that sends *no configuration at all* — what the official SDKs do — was therefore promised a settled task and handed an unsettled one, which would have made us look like the broken party in the first interop run. The response is now held until the task settles, driven by the streaming handler rather than a poll loop: it already broadcasts every transition, so a subscriber *is* the wait. Bounded by `TaskService::with_send_wait` (25s, deliberately *under* the 30s per-request timeout that `JsonRpcClient`, `HttpClient` and `a2acli` all default to — at equal values the two race and a slow agent surfaces as a transport error rather than the unsettled task the bound exists to return); on expiry the *unsettled* task is returned rather than an error, since `WORKING` is true and leaves the caller a task id to follow. A server with no streaming backend cannot observe transitions and degrades to returning what it has rather than failing the send. Breaking: `TaskService::send_message` now takes a `SendOptions` (push config + history limit + `SendCompletion`) in place of two positional `Option`s, and `SendCompletion::WhenSettled` is its `Default` — the wire's polarity is inverted relative to the name, so the enum spells out which branch is which. Streaming calls deliberately ignore `completion`: there, the stream is the wait.
- **BREAKING — clients could not ask for `return_immediately` (`a2a-rs`, `a2a-agents`, `a2acli`)**: making the server block exposed that the client `Transport` port had no way to opt out, which broke two callers that run their own follow-up. `A2aAgentToolSource` (agent-as-tool delegation) polls with its own deadline, and stacking the peer's 25s wait underneath it silently promoted the longer of the two — a 400ms delegation deadline sat behind a 25s server wait, and its test went from 0.5s to 25.5s. `a2acli send --no-wait` had the same shape: it skipped *client-side* polling while the server blocked anyway, so the flag stopped meaning what it says. `Transport::send_task_message` now takes a `SendCompletion`, and `SendCompletion` moved to `domain` (the client port is feature-gate-free and cannot depend on the `server`-gated application layer — and both directions need it). Delegation and `--no-wait` pass `WhenCreated`; the MCP bridge passes `WhenSettled`, since an MCP tool call is request/response with no poll loop of its own. `a2acli`'s poll loop stays as the fallback for servers that ignore the flag.
- **A subscription never ended, on any transport (`a2a-rs`)**: `subscribe`/`message/stream` kept the connection open after the task reached `COMPLETED` or `FAILED`, so `a2acli stream` had to be capped with an external `timeout` and any conformant client read until it gave up. The underlying stream is a broadcast receiver that ends only when the *sender* closes, which never happens — so the end of a stream was derived from nothing. A2A v1.0 removed the `final` flag from `TaskStatusUpdateEvent` (v0.x had one), so the task state is the only thing left to derive it from. The stream now ends after delivering the event that settles the task, via `UpdateEvent::settles_task`. Three things this turned on that are easy to get wrong: it lives in `TaskService`, not in each transport adapter, because both ConnectRPC and JSON-RPC take their stream from there and a check that runs in one entry point and not the other is not a check; *interrupted* states (`INPUT_REQUIRED`, `AUTH_REQUIRED`) settle a stream too, since otherwise the client waits on the agent while the agent waits on the client; and a final artifact chunk does **not**, because `last_chunk` ends an artifact rather than a task and a `WORKING` task may emit several. Subscribing to an already-terminal task short-circuits to an empty stream — but only when no `Last-Event-ID` was given, since resuming on a task that has since finished is exactly when the replay buffer is what the client reconnected for. Replaces the unused `UpdateEvent::is_final`, whose name conflated those last two cases.
- **A queued task could not be canceled (`a2a-rs`)**: both storage adapters accepted `Working` and nothing else, so `cancel` refused a `Submitted` task — work that had not started, which is the clearest thing a client would ever want to stop — and refused `InputRequired` / `AuthRequired`, where cancelling is precisely how a client says "never mind" rather than being obliged to answer. The rule is now "anything that has not finished", expressed once as `TaskState::is_cancelable` (`!is_terminal`) in the domain and consulted by both adapters instead of each carrying its own copy. An unrecognized state counts as cancelable: a peer on a newer protocol may have states this build does not know, and refusing there strands a task no client can be rid of. A test asserts every state is classified exactly once, so one added to the proto cannot slip through unclassified.
- **BREAKING — `EchoResponder` left every task `Working` forever (`a2a-rs`)**: it attached its reply and then reported that the agent was still thinking, so `examples/jsonrpc_server` completed no task it was ever sent. That is a wire-level lie — any conformant A2A client that waits for a terminal state waits forever, which would have been the first thing an interop run against the official `a2aproject/a2acli` hit. An echo has fully processed the message the moment it has the reply, so `Completed` is the only honest state; agents that genuinely acknowledge-now-finish-later implement `AsyncMessageHandler` directly, as the reimbursement agent does. Downstream: a task from the reference echo is now terminal, so it can no longer be canceled (correctly — `TASK_NOT_CANCELABLE`), and the three tests that cancelled an echoed task now drive a task to `Working` explicitly.
- **`a2acli` never printed the agent's reply (`a2acli`)**: `send`, `get`, and `cancel` printed the task id and `state: TASK_STATE_COMPLETED` and nothing else, though the answer was sitting in `status.message.parts[]` — and the `a2a run` banner tells first-time users to run exactly that command, so a freshly scaffolded agent appeared to do nothing. The status message and any artifact content are now rendered, with non-text parts named in brackets rather than dropped (a file part printed bare is indistinguishable from the agent having said its filename). `stream` gained the same for status and artifact events. States render as `completed` / `input-required` rather than the raw proto name, which belongs on the wire and in `--json`.
- **`RuntimeError::DisallowedEnv` answered 500 (`a2a-agents`)**: a config naming secrets the operator has not permitted is the caller's mistake and its message says exactly what to change (`permit them with --allow-env`), but it fell through to the catch-all arm and read — to an operator and to any alerting — as the control plane breaking. Now 400, along with `RuntimeError::Config`.
- **The control plane accepted two agents on one port (`a2a-agents`)**: the cross-agent conflict check only ran within a single `deploy` invocation, never against what was already deployed — so deploying onto a held port reported `ok … healthy` and was wrong twice over: the second agent's process lost the bind race, while the card probe (which knows only the endpoint) answered from the agent that won it, and `ps` admitted `stopped` only later. `ControlPlane::deploy` now runs the same rule `a2a up` runs over a fleet file, against the live fleet, before provisioning anything → `ControlPlaneError::PortInUse` (HTTP 409). A stopped agent holds nothing and never blocks a deploy; redeploying the same id still falls through to the runtime's `AlreadyRunning`.
- **A config with no skills validated clean (`a2a-agents`)**: such an agent is invisible to skill-based peer resolution — an orchestrator never finds it and reports only that no specialist fit. `a2a validate` now warns. Not a failure: an agent reached by explicit `agent_id` is legitimate, and every shipped template declares a skill.
- **`a2a run` / `a2a up` exited 0 when every agent failed to start (`a2a-agents`)**: an agent that could not bind its port was reported only as an `error!` line inside the stderr log stream, while the process exit code said success. The exit code is all any supervisor reads — systemd, a container entrypoint, and this tool's own `LocalProcessRuntime` — so a total failure was indistinguishable from a clean start. Agent tasks now run under a `JoinSet`; each death is reported on **stdout in completion order** (so a fleet member that dies on startup says so at once, rather than when the last agent finally exits), and the command exits non-zero with `N of M agent(s) stopped early`. Surviving agents are deliberately left running — a fleet is more useful degraded than absent — but the exit code no longer lies. Pinned by `tests/run_failure_test.rs`.
- **`cargo install a2a-agents` did not install `a2a` (`a2a-agents`)**: the binary's `required-features` were not all defaults, and cargo *silently skips* such a target rather than reporting it — so the documented install produced only the reimbursement demo, and no doc gave a working command for the product's front door. `default` is now the CLI's feature set (`llm`, `mcp-server`, `schema`, `sqlx`) and the reimbursement sample agent is opt-in behind `reimbursement-agent`. The Dockerfile and the release-binaries workflow no longer pin their own feature lists — the latter had already drifted, building without `llm` and `schema`, which cargo would have refused. `a2a doctor` now reports a `reimbursement` config as an unknown handler when the sample is not compiled in, instead of letting it fall back to echo unannounced. Pinned by `every_feature_the_a2a_binary_requires_is_a_default` and `the_dockerfile_builds_the_binary_with_default_features`.
- **The agent base image could not be built at all (`a2a-agents`)**: the `llm` feature was added to the `a2a` binary's `required-features` and never to the Dockerfile, and cargo refuses to build a named bin whose required features are not all enabled. So `--runtime container` — the *supported* control-plane backend, the only one that survives a restart — had no image. Nothing caught it because the Docker-gated e2e skips green when the image is absent, and an image that cannot be built is absent. Fixed, and pinned by a structural test that parses the manifest and needs no Docker, so it fails in CI (now `every_feature_the_a2a_binary_requires_is_a_default`, which checks the stronger invariant that the required features are all *defaults*).
- **The Dockerfile's pinned toolchain was below what the dependency tree needs (`a2a-agents`)**: `rust:1.85-bookworm` against transitive deps that now require 1.87+, so every image build ended in a wall of "requires rustc 1.8x". Note this is not the same as the crates' own `rust-version`, which is unchanged.
- **No `.dockerignore` (workspace)**: the image builds from the workspace root, so `COPY . .` shipped the entire checkout into the build context on every build — 4.9 GB of it, mostly `target/` and the vendored `a2a-mcp/rust-sdk` submodule — including host build artifacts for a different target triple that the builder then ignored and rebuilt. Context is now 5.35 MB and transfers in seconds. Note the patterns are written *without* trailing slashes: Docker matches with Go's `filepath.Match`, where `target/` silently excludes nothing (the first version of this file used trailing slashes and made no difference at all).
- **`a2a` logged to stdout, mixing into its own reports (`a2a-agents`)**: `tracing_subscriber::fmt()` defaults to stdout, so `a2a validate > report.txt` captured whatever happened to be logged alongside the report the command exists to produce — the very split the CLI's output design assumed. Logs now go to stderr.
- **Captured agent logs carried terminal escape codes (`a2a-agents`)**: colour was emitted unconditionally, including when a supervised agent's output was being written straight into a log file. It is now gated on `stderr().is_terminal()`.
- **`a2a ps` / `GET /agents` returned agents in arbitrary order (`a2a-agents`)**: the order was the runtime's map's, so it shuffled between calls and made the listing undiffable. `ControlPlane::list` sorts by id.
- **`a2a control-plane` logged the requested bind, not the bound one (`a2a-agents`)**: with `--bind 127.0.0.1:0` (or a hostname) the announced URL was not one a caller could use. It now reports `local_addr()`.
- **Agent cards advertised the wrong transport (`a2a-rs`)**: `HttpServer` mounts *only* the ConnectRPC router, but a card built via `SimpleAgentInfo::new` defaulted its primary interface to `JSONRPC`, so every `HttpServer` published a card that lied about itself and card-driven clients negotiated to an endpoint that was never mounted (`invalid JSON-RPC response: error decoding response body`). `HttpServer` now stamps `CONNECTRPC` on the card it serves, and `a2a-agents` sets it at the source for the readers that bypass HTTP — registry self-registration and MCP mode. This unblocked agent-as-tool delegation and skill discovery, both of which rest on that negotiation.
- **`a2a run` was completely silent (`a2a-agents`)**: `EnvFilter::from_default_env()` enables nothing when `RUST_LOG` is unset, so `run` started a server and printed no confirmation, no URL, and no errors. The default is now `warn` globally with our own crates at `info`; `RUST_LOG` still overrides entirely.
- **AgentId lookups are canonicalized (`a2a-agents`)**: `From`/`FromStr` route through `slugify`, so a non-canonical lookup key — an HTTP path parameter, a config `agent_id` reference — resolves instead of silently missing the slugified keyspace. `slugify` also collapses separator runs.
- **Environment-variable expansion in TOML config was widened (`a2a-agents`)**: `${VAR:-default}` is honoured (a missing variable takes the default, otherwise it is a hard error), and the pattern now matches lower/mixed-case names — it was `[A-Z_]`-only, so `${database_url}` passed through literally rather than erroring.
- **`reasoning_enabled` is driven by the provider, not the environment (`a2a-agents`)**: it now comes from `LlmProvider::supports_reasoning()` instead of env-sniffing.

### Documentation
- **Workspace docs consolidated to three files.** `TODO.md`, `DECLARATIVE_AGENTS_TODO.md`, `DECLARATIVE_AGENTS.md`, and `ROADMAP.md` were four documents with overlapping and drifting jurisdictions — the platform overview largely duplicated `a2a-agents/README.md`, the roadmap's headline item had already shipped, and open work was split across two TODO files by an accident of history rather than by topic. Now:
  - `TODO.md` — all open work, one file, ordered; deferred themes are sections in it rather than a separate document.
  - `NOTES.md` (new) — the *why*: decisions worth not re-litigating, load-bearing defaults, and hazards that will recur. This is the content that outlived its task and does not belong in a changelog.
  - `CHANGELOG.md` — what changed, per release.
  - Usage documentation now lives with the crate it documents; the platform overview was folded into `a2a-agents/README.md` (which gains the config-is-the-source-of-truth diagram). `CLAUDE.md` states the split so it does not drift back.

## [0.4.0] - 2026-06-05

### Added
- **Client-side `Transport` port + JSON-RPC 2.0 client + card-driven negotiation (`a2a-rs`)**: The client gained a hexagonal transport abstraction mirroring the server side, plus a wire-compatible JSON-RPC 2.0 client so it can talk to any standard A2A agent.
  - `port::client::Transport` (re-exported as `a2a_rs::Transport`) is the outbound client port — the renamed, relocated `AsyncA2AClient` with an added `protocol()` discriminator. `HttpClient` (ConnectRPC) reports `"CONNECTRPC"`.
  - `JsonRpcClient` (new `jsonrpc-client` feature) implements `Transport` over the spec JSON-RPC 2.0 wire format (single `POST`, SSE for streaming), reusing the generated ProtoJSON request/response types. Its method names, error codes, and envelopes come from a shared `adapter::transport::jsonrpc_wire` module extracted from the server adapter, so the two directions are byte-compatible (proven by `tests/jsonrpc_client_interop_test.rs`, an in-process client↔server round-trip over a real socket: send/get/list/cancel, push-config CRUD, SSE subscribe, typed error mapping).
  - `TransportFactory` + `TransportNegotiator` + `connect(base_url, &negotiator)` select a transport from an agent card's `supported_interfaces`, ranked by client preference (factory registration order). `default_registry()` prefers CONNECTRPC then JSON-RPC. Unit tests in `tests/transport_negotiation_test.rs`.
  - `a2a-web-client`'s `WebA2AClient` now holds a `Box<dyn Transport>` (field `transport`, was `http`); `auto_connect` performs real card-driven negotiation, falling back to a direct ConnectRPC client.
- **Wire-compatible JSON-RPC 2.0 + HTTP+JSON transport (`a2a-rs`)**: Added `JsonRpcAdapter`, a sibling of `ConnectRpcAdapter` that speaks the spec-mandated JSON-RPC 2.0 and HTTP+JSON (REST) bindings for interop with the canonical `a2aproject` SDK (and the Go/C#/Python SDKs). Behind the new `jsonrpc-server` feature.
  - Wraps the same inner `TaskService`; mounted at the composition edge via the `jsonrpc_router` / `rest_router` free functions (see `examples/jsonrpc_server.rs`).
  - JSON-RPC: single `POST /` with all 11 methods (`SendMessage`, `GetTask`, `ListTasks`, `CancelTask`, push-config CRUD, `GetExtendedAgentCard`), `A2AError` → spec error codes (`-32001`…, `-32700`/`-32601`/`-32602`), and SSE for the two streaming methods.

Task custom-verbs use slash-form aliases (`/tasks/{id}/cancel`) since axum's matchit router rejects a path-param + `:`-suffix in one segment.
  - The wire body reuses the `buffa`-generated proto request/response types directly: verified ProtoJSON-clean (camelCase, SCREAMING_SNAKE enums, RFC3339 timestamps, base64 `bytes`, bare `Struct` metadata, tag-free field-presence unions), so no hand-written wire DTOs are needed. Golden + behavioral tests in `tests/jsonrpc_wire_test.rs` and `tests/jsonrpc_dispatch_test.rs`.
  - End-to-end router tests in `tests/jsonrpc_router_test.rs` drive the real `jsonrpc_router`/`rest_router` via `tower::ServiceExt::oneshot`: REST round-trip, the `/tasks/{id}/cancel` slash alias, 404/error-status mapping, list-via-query, the JSON-RPC envelope + version rejection, and both SSE framings (JSON-RPC wraps each event in a response envelope; REST emits the bare ProtoJSON `StreamResponse`).
