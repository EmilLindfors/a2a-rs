# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **`a2a deploy` / `ps` / `logs` / `stop` — the CLI half of the control plane (`a2a-agents`)**: the server half already existed and nothing but `curl` could work it, which left the whole daemon story reachable only through Terraform. The same binary is now both halves, over a new first-class `ControlPlaneClient` adapter (the Terraform provider will target the same routes). `--url` / `--token` fall back to `A2A_CONTROL_PLANE_URL` / `A2A_CONTROL_PLANE_TOKEN` and then to where `a2a control-plane` binds, so a control plane in one terminal and these commands in another need no configuration to find each other.
  - Configs are deployed **raw**: `${VAR}` is expanded by the control plane against *its* environment and *its* `--allow-env` allowlist. Expanding client-side would put the operator's secrets on the wire, require every deploying machine to hold them, and bypass the allowlist entirely.
  - `deploy` takes `--config` (repeatable) or `--fleet <toml>`, and checks shape plus the cross-agent conflict rules *before sending anything* — a port clash knowable up front must not leave half a fleet deployed.
  - The request/response bodies now live in one place (`control_plane::wire`), shared by the router and the client, so the two sides cannot drift.
- **`AgentRuntime::logs` (`a2a-agents`)**: health says an agent is `unhealthy`; this says why. `GET /agents/{id}/logs?tail=N` on the API, `a2a logs <id> [--tail N]` on the CLI. `ContainerRuntime` replays through the engine, merging **both** streams — an agent's `tracing` output goes to stderr, so reading stdout alone showed an empty log for a crashing agent. `LocalProcessRuntime` captures each agent into `<log-dir>/<id>.log` (`a2a control-plane --log-dir`, defaulting to `<config-dir>/logs`), which also stops every agent's output interleaving into the supervisor's terminal unlabelled.
- **Restart-recovery for the control plane (`a2a-agents`)**: a bounced control plane used to come back reporting an empty fleet while its agents were still serving — `GET /agents` returned `[]`, `DELETE` returned 404, peers stopped resolving each other by skill, and a Terraform `Read` would conclude the agents had been destroyed and recreate them on top of the running ones. New `AgentRuntime::recover` adopts what the backend is still running, and `ControlPlane::recover` re-registers the adopted agents' cards so discovery is rebuilt *from the runtime* rather than from a database. `a2a control-plane` runs it before binding, so the API's first answer is true.
  - The return type is `Recovered::{Adopted, Ephemeral}`, because "nothing was running" and "I cannot tell what is running" are different answers and only the first may be reported as an empty fleet. Every adapter must state which — there is deliberately no defaulted trait method.
  - `ContainerRuntime` rebuilds its `AgentId → port` map from `docker ps -a --filter label=a2a-agent`; provisioning now also stamps the published port as a label so the map is recovered whole rather than half. `LocalProcessRuntime` answers `Ephemeral` (its children die with the supervisor), which is the concrete reason container is the supported control-plane backend.
  - New `CardSource` port (+ `HttpCardSource` / `InMemoryCardSource`) so re-registration does not put an HTTP client in the service layer, and recovery is testable without a network.
- **`a2a doctor` — pre-flight check (`a2a-agents`)**: `validate` answers "is this config well-formed"; `doctor` answers "will it work on this machine" — is the port free, is the MCP server's command on `PATH`, is a model key set, does every `${VAR}` resolve *here*, is a container engine installed, and can the configs named actually run together. Split so the rules are testable: `core::doctor::requirements` derives what a config needs purely from the config, and the binary probes the host (bind the port, search `PATH` honouring `PATHEXT`, read the environment). Only *problems* set the exit code; warnings describe something that will run, differently than you may have meant. Deliberately stricter than `validate` on one point — an unset `${VAR}` is reported there and fatal here, because `a2a run` refuses to start until it resolves.
- **`a2a up` — run a fleet from one file (`a2a-agents`)**: a fleet file lists member agent configs by path (resolved relative to itself, so a fleet runs from any directory), replacing a `--config` per agent on every invocation with one reviewable artifact. It redefines nothing about an agent — `AgentConfig` stays the source of truth — and adds the checks that only exist *between* members, run before anything binds: two agents claiming the same **port**, and two names that slugify to the same **registry id**. Both are silent-wrong at runtime (a bind error buried in a process that otherwise came up; registration upsert, so delegation by skill/`agent_id` reaches only the last one). `a2a validate --fleet <toml>` runs the same check without starting anything and reports every conflict rather than the first; `a2a print-schema --fleet` emits the `FleetConfig` schema. New `core::fleet` module (`FleetConfig`, `fleet_conflicts`) plus `examples/fleet.toml`.
- **`a2a new` — scaffold an agent config (`a2a-agents`)**: `a2a new <name> [--template echo|llm|mcp|orchestrator]` writes a commented, immediately-runnable TOML and prints the next commands. Templates are written to be *read* — every non-obvious key carries a comment — so a generated file answers "what else can go here?" without `print-schema`. `--output`, `--port`, `--force`; an existing file is never clobbered by default. Rendering lives in `core::template` as a pure function (file I/O stays in the binary), and tests pin the two invariants that make a scaffold trustworthy: every template must *validate*, and no template may reference `${VAR}` — a freshly scaffolded agent has to run without the user setting something first.
- **Control-plane authentication (`a2a-agents`)**: `ControlPlaneAuth` (bearer token, constant-time compare) is a **required parameter** of `control_plane_router`, so an unauthenticated control plane cannot happen by omission — `ControlPlaneAuth::Disabled` has to be written out. `a2a control-plane` refuses to start without `--token` / `A2A_CONTROL_PLANE_TOKEN` unless `--no-auth` is passed, which warns loudly.
- **Secrets allowlist for deployed agents (`a2a-agents`)**: `EnvAllowlist` (deny-by-default) replaces "inject whatever the config references". Configured once at the composition edge (`--allow-env VAR`, repeatable) and given to both the `ControlPlane` (vets what the API accepts) and the runtime adapter (decides what crosses into the agent), so the runtime stays safe even when something other than the service drives it. The check runs against the **raw** TOML before parsing, because parsing expands `${VAR}` and reports set vs. unset differently — otherwise a config naming a forbidden secret is a probe for which secrets the control plane holds.
- **`a2a validate` reports unresolved env refs (`a2a-agents`)**: unset `${VAR}` references no longer fail the check; they are substituted with a placeholder and listed, so a config's *shape* is verifiable without the secrets it will run with (`AgentConfig::check_toml`). `--strict-env` restores hard failure as a pre-deploy gate. Leniency is scoped to missing values only — structural checking is untouched.
- **`a2a run` startup banner (`a2a-agents`)**: prints each agent's name, URL, card URL, and a copy-pasteable `a2acli send` / `curl`, on stdout rather than through `tracing`.
- **Protocol-binding constants (`a2a-rs`)**: `PROTOCOL_BINDING_JSONRPC` / `_CONNECTRPC` / `_HTTP_JSON` in `domain`, shared by the agent-card builder and the client negotiation factories so the two sides cannot drift apart.
- **Declarative multi-agent platform (`a2a-agents`)**: `a2a-agents` grew from a single-agent builder into a platform for running and orchestrating *many* agents, with every outward capability defined as a **port** so the core `a2a-rs` protocol crate stays infrastructure-free.
  - **Agent-as-tool delegation**: a config-driven `LlmHandler` (behind the `llm` feature) can call peer A2A agents and MCP servers as tools — an orchestrator delegates work by listing peers under `[[handler.llm.agents]]` and tool sources under `[[handler.llm.mcp]]`. The handler no longer depends on `mcp-server`; LLM provider selection routes through the shared provider helper.
  - **Registry / discovery**: the `AgentRegistry` port + `InMemoryAgentRegistry` let agents find peers by **skill** instead of hard-coded URLs. Config refs resolve by `skill`/`agent_id`; the `a2a` binary self-registers in a two-phase startup.
  - **Runtime / isolation**: one `AgentRuntime` port supervises agents as local processes or OCI containers — `LocalProcessRuntime`, `ContainerRuntime` (CLI shell-out backend), and `InMemoryAgentRuntime` for tests. Sandboxing lives in the platform, not in `a2a-rs`.
  - **Control plane**: a `ControlPlane` service composes runtime + registry behind an HTTP API; `a2a control-plane` deploys, lists, and tears down agents (deploy is async).
  - **`terraform-provider-a2aagent`** (WIP): a Terraform provider for declaring agents as infrastructure.
- **OpenRouter LLM provider + reasoning (`a2a-agents-common`)**: added an OpenRouter provider with centralized provider selection and reasoning-token support; the `complex_agent` example streams GLM reasoning and answer tokens live over SSE.
- **`a2acli` command-line client**: a new CLI driving the `a2a-rs` `Transport` port — `card`, `send`, `get`, `cancel`, `stream`. Endpoint from `A2A_URL` (`--url`/`-u`); `--transport auto|connectrpc|jsonrpc`; `--json` for machine-readable output. Auto mode negotiates the transport from the agent card with a direct-client fallback, doubling as a manual cross-SDK interop harness. `auto_connect` was promoted into `a2a-rs` and is now shared by the CLI and web client.

### Changed
- **BREAKING — `AgentRuntime` gained a required `logs` method (`a2a-agents`)**: no default implementation, for the same reason `recover` has none — a backend that keeps no logs must return the new `RuntimeError::Unsupported` (surfaced as HTTP 501) rather than an empty list, because "the agent printed nothing" and "this runtime does not record output" send an operator to opposite places. All in-workspace adapters are updated in the same change (pre-1.0, no shim).
- **BREAKING — `AgentRuntime` gained a required `recover` method (`a2a-agents`)**: no default implementation, so every adapter has to state whether it can be recovered after a restart. A default returning "nothing" would have been the exact silent-wrong this feature exists to remove. All in-workspace adapters are updated in the same change (pre-1.0, no shim).
- **BREAKING — `ControlPlane::new` takes a `CardSource` (`a2a-agents`)**: recovery has to fetch a running agent's card to put it back into discovery, and a control plane that silently skipped that step would come back from a restart supervising agents nobody can find. Required rather than optional for that reason.
- **BREAKING — unknown config keys are now errors (`a2a-agents`)**: every config struct is `#[serde(deny_unknown_fields)]`. Previously a mistyped key was silently ignored, so `http_prot = 9999` validated clean and then served on 8080 — the config lied and the checker agreed. Errors now point at the line, name the key, and list the valid ones. Configs carrying stray keys will start failing; all 17 shipped examples were already clean.
- **BREAKING — control-plane deploy is gated by a token type (`a2a-agents`)**: `ControlPlane::prepare(raw_toml)` returns a `PreparedDeploy` that is the only thing `deploy` accepts, making the policy check unskippable by construction rather than by convention. `control_plane_router` gained a required `ControlPlaneAuth` argument. In-workspace call sites are updated in the same change (pre-1.0, no shim).
- **BREAKING — runtime type renamed (`a2a-agents`)**: the old single-agent server type `core::AgentRuntime<H, S>` is now `AgentServer`; `AgentRuntime` is the new platform runtime **port**. In-workspace call sites are updated in the same change (pre-1.0, no shim).
- **Validation output is CLI output (`a2a-agents`)**: `a2a validate` results go to stdout without timestamps, levels, or module paths — one indented block per file with a summary line. Long-running commands (`run`, `control-plane`) still use `tracing`.

### Fixed
- **`a2a` logged to stdout, mixing into its own reports (`a2a-agents`)**: `tracing_subscriber::fmt()` defaults to stdout, so `a2a validate > report.txt` captured whatever happened to be logged alongside the report the command exists to produce — the very split the CLI's output design assumed. Logs now go to stderr.
- **Captured agent logs carried terminal escape codes (`a2a-agents`)**: colour was emitted unconditionally, including when a supervised agent's output was being written straight into a log file. It is now gated on `stderr().is_terminal()`.
- **`a2a ps` / `GET /agents` returned agents in arbitrary order (`a2a-agents`)**: the order was the runtime's map's, so it shuffled between calls and made the listing undiffable. `ControlPlane::list` sorts by id.
- **`a2a control-plane` logged the requested bind, not the bound one (`a2a-agents`)**: with `--bind 127.0.0.1:0` (or a hostname) the announced URL was not one a caller could use. It now reports `local_addr()`.
- **Agent cards advertised the wrong transport (`a2a-rs`)**: `HttpServer` mounts *only* the ConnectRPC router, but a card built via `SimpleAgentInfo::new` defaulted its primary interface to `JSONRPC`, so every `HttpServer` published a card that lied about itself and card-driven clients negotiated to an endpoint that was never mounted (`invalid JSON-RPC response: error decoding response body`). `HttpServer` now stamps `CONNECTRPC` on the card it serves, and `a2a-agents` sets it at the source for the readers that bypass HTTP — registry self-registration and MCP mode. This unblocked agent-as-tool delegation and skill discovery, both of which rest on that negotiation.
- **`a2a run` was completely silent (`a2a-agents`)**: `EnvFilter::from_default_env()` enables nothing when `RUST_LOG` is unset, so `run` started a server and printed no confirmation, no URL, and no errors. The default is now `warn` globally with our own crates at `info`; `RUST_LOG` still overrides entirely.
- **AgentId lookups are canonicalized (`a2a-agents`)** and environment-variable expansion in TOML config was widened.

## [0.4.0] - 2026-06-05

### Added
- **Client-side `Transport` port + JSON-RPC 2.0 client + card-driven negotiation (`a2a-rs`)**: The client gained a hexagonal transport abstraction mirroring the server side, plus a wire-compatible JSON-RPC 2.0 client so it can talk to any standard A2A agent.
  - `port::client::Transport` (re-exported as `a2a_rs::Transport`) is the outbound client port — the renamed, relocated `AsyncA2AClient` with an added `protocol()` discriminator. `HttpClient` (ConnectRPC) reports `"CONNECTRPC"`.
  - `JsonRpcClient` (new `jsonrpc-client` feature) implements `Transport` over the spec JSON-RPC 2.0 wire format (single `POST`, SSE for streaming), reusing the generated ProtoJSON request/response types. Its method names, error codes, and envelopes come from a shared `adapter::transport::jsonrpc_wire` module extracted from the server adapter, so the two directions are byte-compatible (proven by `tests/jsonrpc_client_interop_test.rs`, an in-process client↔server round-trip over a real socket: send/get/list/cancel, push-config CRUD, SSE subscribe, typed error mapping).
  - `TransportFactory` + `TransportNegotiator` + `connect(base_url, &negotiator)` select a transport from an agent card's `supported_interfaces`, ranked by client preference (factory registration order). `default_registry()` prefers CONNECTRPC then JSON-RPC. Unit tests in `tests/transport_negotiation_test.rs`.
  - `a2a-web-client`'s `WebA2AClient` now holds a `Box<dyn Transport>` (field `transport`, was `http`); `auto_connect` performs real card-driven negotiation, falling back to a direct ConnectRPC client.
- **Wire-compatible JSON-RPC 2.0 + HTTP+JSON transport (`a2a-rs`)**: Added `JsonRpcAdapter`, a sibling of `ConnectRpcAdapter` that speaks the spec-mandated JSON-RPC 2.0 and HTTP+JSON (REST) bindings for interop with the canonical `a2aproject` SDK (and the Go/C#/Python SDKs). Behind the new `jsonrpc-server` feature.
  - Wraps the same inner `TaskService`; mounted at the composition edge via the `jsonrpc_router` / `rest_router` free functions (see `examples/jsonrpc_server.rs`).
  - JSON-RPC: single `POST /` with all 11 methods (`SendMessage`, `GetTask`, `ListTasks`, `CancelTask`, push-config CRUD, `GetExtendedAgentCard`), `A2AError` → spec error codes (`-32001`…, `-32700`/`-32601`/`-32602`), and SSE for the two streaming methods.
  - REST: official-SDK paths (no `/v1` prefix) — `POST /message:send`, `GET /tasks/{id}`, `GET /extendedAgentCard`, push-config routes — with HTTP status mapped from `A2AError`. Task custom-verbs use slash-form aliases (`/tasks/{id}/cancel`) since axum's matchit router rejects a path-param + `:`-suffix in one segment.
  - The wire body reuses the `buffa`-generated proto request/response types directly: verified ProtoJSON-clean (camelCase, SCREAMING_SNAKE enums, RFC3339 timestamps, base64 `bytes`, bare `Struct` metadata, tag-free field-presence unions), so no hand-written wire DTOs are needed. Golden + behavioral tests in `tests/jsonrpc_wire_test.rs` and `tests/jsonrpc_dispatch_test.rs`.
  - End-to-end router tests in `tests/jsonrpc_router_test.rs` drive the real `jsonrpc_router`/`rest_router` via `tower::ServiceExt::oneshot`: REST round-trip, the `/tasks/{id}/cancel` slash alias, 404/error-status mapping, list-via-query, the JSON-RPC envelope + version rejection, and both SSE framings (JSON-RPC wraps each event in a response envelope; REST emits the bare ProtoJSON `StreamResponse`).
- **Agent-card transport negotiation (`a2a-rs`)**: `SimpleAgentInfo` gained `with_preferred_transport` and `add_interface` so a card can advertise multiple `supportedInterfaces` (e.g. `JSONRPC` + `HTTP+JSON`) — the metadata an off-the-shelf A2A client reads to negotiate a transport. `examples/jsonrpc_server.rs` advertises both bindings it mounts.
- **Native LLM Tool Calling**: Added `LlmProvider` primitives (`ToolDefinition`, `ToolCall`) to `a2a-agents-common` for standardizing function calling across models (OpenAI, Gemini).
- **LLM Streaming Support (SSE)**: Added `chat_completion_stream` to stream content and fully formed tool calls in real time.
- **AI/LLM Integration (Phase 3)**: Integrated `McpClientManager` into `AgentBuilder` via the `mcp-client` feature.
- **a2a-mcp Integration Examples**:
  - `a2a_as_mcp_server.rs`: A2A agent exposed as MCP tools via `AgentToMcpBridge`.
  - `a2a_with_mcp_tools.rs`: A2A handler augmented with MCP tools via `McpToA2ABridge`.
  - `bidirectional_demo.rs`: Both bridges running in one process.
- **a2a-mcp Feature Completions**:
  - Bridged A2A `message/stream` ↔ MCP progress/sampling.
  - Bridged A2A artifacts ↔ MCP resources.
  - Bridged A2A skills ↔ MCP prompts.
  - Bridged A2A `SecurityScheme` ↔ MCP auth.
  - Added support for task cancellation propagation across bridges.
  - Added task resubscription on `McpToA2ABridge` (handled natively by A2A task storage).
  - Added in-process A2A handler backend for `AgentToMcpBridge` (`AgentToMcpBridge::with_handler` / `with_handler_and_namespace`).
- **Interactive Forms & Follow-ups over MCP**: Addressed via the Sampling API in `AgentToMcpBridge` (managing the `InputRequired` state).
- **Authentication Flows over MCP**: `AuthRequired` state mapped to `InputRequired` in MCP, correctly passing auth flows to LLMs.
- **Long-Running Tasks & Progress Streaming**: Implemented streaming bridge mapped to `notifications/progress` and A2A artifacts.
- **Testing & Coverage**: Added unit tests to `a2a-client`, `a2a-agents-common` and a comprehensive e2e framework lifecycle test.
- **Documentation**:
  - Documented the metadata tool-call envelope used by `McpToA2ABridge` in `lib.rs` crate-level rustdoc and the bridge's struct docs.
  - Added an architecture diagram to the `a2a-mcp` README.
  - Converted rustdoc examples in `a2a-mcp`'s `lib.rs` from `rust,ignore` to real compile-checked `no_run` doctests.
- **Kitchen-sink complex agent example (`a2a-agents`)**: `examples/complex_agent.rs` (+ `complex_agent.toml`, behind `--features mcp-server`) — a "Research Assistant" wiring every major building block in one binary: declarative TOML config, optional LLM tool-calling via `LlmProvider` (with a keyless rule-based fallback), MCP tool consumption through `McpToA2ABridge` against an in-process tool server, live SSE streaming of progress artifacts, and native A2A task lifecycle via the `TaskStatusBroadcast` mixin.
- **Builder-level streaming wiring (`a2a-agents` + `a2a-rs`)**: `AgentBuilder::with_streaming` / `AgentRuntime::with_streaming` attach a shared streaming backend that the runtime injects into the transport (`ConnectRpcAdapter::with_streaming_handler`), so `tasks/subscribe` SSE streams finally observe the broadcasts a handler emits. Backed by a new forwarding blanket `impl AsyncStreamingHandler for Arc<dyn AsyncStreamingHandler>` in `a2a-rs`. **Fixes** a gap where the builder path defaulted to a no-op streaming handler and silently dropped handler broadcasts before they reached SSE clients.

### Changed
- **`a2a-rs` transport**: Extracted the ConnectRPC adapter's request-decoding helpers (`decode_send_config`, `list_request_to_params`, `map_update_event`) to `pub(super)` so the new JSON-RPC adapter reuses them — both transports now share a single decode/encode path against the generated proto types.
- **BREAKING — client port renamed and relocated (`a2a-rs`)**: The client trait `services::client::AsyncA2AClient` is now `port::client::Transport` (re-exported as `a2a_rs::Transport`), with a new required `fn protocol(&self) -> &str` method. `StreamItem` moved alongside it (`a2a_rs::StreamItem`). The `services::client` module and the `services::{AsyncA2AClient, StreamItem}` re-exports are gone. Call sites import `a2a_rs::Transport` / `a2a_rs::StreamItem`; method names are unchanged. `a2a-web-client`'s `WebA2AClient.http: HttpClient` field became `transport: Box<dyn Transport>`.

### Removed
- Removed the printf-only `examples/minimal_example.rs` in `a2a-mcp`.
